# RiverShift independent reference validation runbook

## What this workflow validates

The first automated independent-reference workflow evaluates the retained event-proximal
binary water mask at outputs/flood/during_water_mask.tif. It compares NISAR GCOV
water/non-water classification with a separately produced binary reference raster.

It reports a confusion matrix, precision (user's accuracy), recall (producer's accuracy),
F1, IoU, specificity, Cohen's kappa, area bias, and spatial-block bootstrap intervals.
It does **not** validate riverbank erosion/deposition, sediment transport, channel migration,
or event causality. Those require independent bankline or geomorphic reference evidence.

## Required reference raster

Prepare a GeoTIFF with:

- One binary band: 1 = water, 0 = non-water.
- Any valid georeferenced CRS and affine transform; the runner aligns categorical
  labels to the NISAR mask grid with nearest-neighbour resampling.
- Exactly one band with binary values 0/1 and NoData for genuinely unlabelled pixels.
- Do not resample labels yourself to match the NISAR pixel grid; the workflow records
  the reference source grid and performs the reproducible alignment internally.
- NoData only for genuinely unlabelled / invalid reference pixels.
- A source, acquisition/observation date, and reproducible classification/QA method.

The default temporal gate is an absolute reference-to-NISAR observation offset of at most
3 days. This is a conservative default, not a universal hydrological rule: the reference
must also represent a comparable river stage and event state. A reviewer can choose a
larger offset only when the hydrological comparability is justified and documented.

The default common valid support gate is 80% of the NISAR prediction-valid footprint.
A run below the selected gate stops without publishing classification metrics. The
reference must not be generated by copying, threshold-tuning against, or otherwise
reusing the NISAR prediction being evaluated.

## Run it

1. Prepare the independent binary GeoTIFF and upload it to the same Google Drive account
   used for SARGuardian's private RiverShift result storage. Keep the file private.
2. Copy the file ID from its Drive URL. Do not change sharing to "Anyone with the link".
3. After the Dynamic API's signed validation-input endpoint and this workflow are merged
   and deployed, open the backend repository's Actions tab.
4. Select RiverShift independent reference validation and click Run workflow.
5. Use the source job UUID. The default is the retained example job
   4e6e4071-fb9d-4e20-a331-867f3f2bd88f, whose event-proximal NISAR water observation
   is 2026-08-17.
6. Supply the reference Drive file ID, source/product, reference date, and the exact
   production method and QA/review method. Keep the 3-day / 80% defaults unless a
   documented reason supports another choice.
7. Download the generated river-shift-independent-validation-<job-id> JSON artifact
   from the completed Actions run.

The workflow resolves the NISAR mask and its adjacent river_shift_result.json through
a signed, read-only Dynamic API endpoint. It verifies both retained Drive receipts
against their SHA-256 checksums before validation. The reference is independently
checksum-recorded, checked for binary labels, aligned onto the NISAR projected-metre
grid with nearest-neighbour resampling, and then tested for common valid support.
NoData is preserved rather than filled. The original processing job and its immutable
record are never modified.

## Interpret the result

VALIDATION_METRICS_COMPUTED_REVIEW_REQUIRED means only that the declared reference
passed the technical gates and metrics were computed. It is not a scientific release
approval. The JSON report deliberately keeps:

- reference.independence_verified = false
- quality.release_status = PROVISIONAL
- quality.status = VALIDATION_METRICS_COMPUTED_REVIEW_REQUIRED

A qualified reviewer must inspect the reference provenance, temporal/hydrological
comparability, geolocation, class definition, label QA, class balance, confusion matrix,
and spatial-block intervals. If there are fewer than 20 valid spatial blocks, the report
will not estimate bootstrap intervals. Do not interpret the pixel bootstrap as independent
samples; uncertainty is summarized at the declared spatial-block scale.

A cloud-filtered Sentinel-2-derived water mask is useful as cross-sensor agreement
evidence, but it is not automatically ground truth. High-resolution reference mapping,
field/UAV observations, gauge context and/or independently reviewed labels provide
stronger evidence depending on the claim.

## Separate morphology validation

The workflow above must not be used to validate erosion/deposition candidate masks.
Morphology validation needs independently mapped pre/post banklines or channel boundaries
on comparable dates, a declared positional uncertainty, signed cross-section/transect
analysis, and review of the direction and magnitude of bankline movement. Candidate
polygons and low-resolution web previews are not reference data.
